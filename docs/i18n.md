# Translating the interface

Only the **interface** is translated: TUI labels, the setup and help panes, the
first-run wizard, keybinding hints. Log records and `--json` output stay in
English — they are machine-facing, and a localised log is a log nobody can grep
or paste into an issue.

## Adding a string

1. Add a field to `Strings` in `src/i18n/mod.rs`.
2. Fill it in for English in the `EN` constant.
3. The build now fails for `ru`, `pl` and `lt` until each supplies it.

That failure is the design. There is no runtime lookup and no fallback to
English, so a half-translated build cannot ship by accident.

## Adding a language

1. Add a variant to `Lang`, plus its `code()`, `endonym()` and `parse()` arms.
2. Create `src/i18n/<code>.rs` with a `static` of the same shape.
3. Wire it into `Lang::strings()`.

`endonym()` must be the language's name *in that language* — someone opening the
picker may not read any of the others.

## Notes for translators

- Keep panel titles to one or two words; they sit in a bordered header and are
  truncated, not wrapped.
- Keybinding hints share a single footer line. Shorter is better than literal.
- `size`, `language`, `mode`, `dry run` are padded to a 10-column label. A
  longer word is fine but will push the value right.
- Don't translate: provider names, environment variable names, URLs, CLI
  commands like `spotify-agent login`.
